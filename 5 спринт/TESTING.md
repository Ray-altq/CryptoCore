# Проверки пятого спринта

На этапе подготовки сохранены код, тесты и результаты четвёртого спринта. Приведённые ниже результаты NIST и большого файла относятся к четвёртому спринту. Проверки HMAC будут добавлены вместе с реализацией.

# Проверка CSPRNG через NIST STS

Для статистической проверки используется официальный набор NIST SP 800-22 Rev. 1a. Исходный код и документация доступны на [странице NIST](https://csrc.nist.gov/projects/random-bit-generation/documentation-and-software).

Статистические тесты не доказывают криптографическую стойкость генератора. Они используются как дополнительная проверка выходных данных `os.urandom()`.

## Подготовка данных

Сначала установите проект и создайте бинарный файл размером 10 МБ:

```powershell
python -m pip install -e ".[dev]"
python scripts/generate_nist_data.py --size-mb 10 --output nist_random.bin
```

Файл содержит 80 000 000 бит. Для NIST STS он разбивается на 80 потоков по 1 000 000 бит.

## Запуск NIST STS

Скачайте NIST Statistical Test Suite с официальной страницы, распакуйте архив и соберите программу `assess` по инструкции из комплекта.

Из каталога NIST STS запустите:

```bash
./assess 1000000
```

В интерактивном меню укажите:

1. Источник данных: `Input File`.
2. Путь к созданному `nist_random.bin`.
3. Формат данных: `Binary`.
4. Набор тестов: все 15 тестов.
5. Параметры тестов: значения по умолчанию.
6. Количество потоков: `80`.

Итоговый отчёт создаётся в `experiments/AlgorithmTesting/finalAnalysisReport.txt`. Для успешной проверки большинство тестов должно иметь `p-value >= 0.01`. Единичные статистические отклонения допустимы, массовые ошибки требуют проверки генератора и входного файла.

## Результаты

Проверка выполнена 12 октября 2026 года с помощью официального NIST STS 2.1.2.

- Источник данных: `generate_random_bytes()` на основе `os.urandom()`.
- Размер файла: 10 000 000 байт.
- Размер одного потока: 1 000 000 бит.
- Количество потоков: 80.
- Формат: Binary.
- Запущены все 15 тестов со стандартными параметрами.
- В итоговом отчёте получено 188 строк результатов с учётом подвариантов тестов.
- Все доли прошедших последовательностей соответствуют минимальным порогам NIST: не менее 76 из 80 и не менее 55 из 58 для Random Excursions.

Три подрезультата показали равномерность p-value ниже `0.01`:

| Тест | P-value | Прошло потоков |
| --- | ---: | ---: |
| Approximate Entropy | 0.001691 | 79/80 |
| Random Excursions | 0.006661 | 58/58 |
| Random Excursions Variant | 0.002758 | 57/58 |

Остальные 185 строк имеют p-value не ниже `0.01`. Единичные отклонения ожидаемы при большом числе статистических проверок, а все показатели доли прохождения находятся выше минимальных порогов. По критериям третьего спринта проверка считается успешной.

Полный исходный отчёт сохранён в `nist_results/finalAnalysisReport.txt`.

## Хеширование файла больше 1 ГБ

Из папки `5 спринт` с установленным проектом запустите:

```bash
python scripts/check_large_hash.py
```

Скрипт создаёт временный файл размером 1 100 000 000 байт (больше 1 ГиБ) и проверяет SHA-256 и SHA3-256 через рабочую функцию `hash_stream`. Данные читаются частями не больше 8192 байт и одновременно передаются эталонному алгоритму из `hashlib`. При несовпадении хешей программа завершается с кодом 1. При успехе выводятся `[OK]`, хеш и время обработки каждого алгоритма. Прогресс выводится примерно раз в 10 секунд.

Понадобится около 1,1 ГБ свободного места в системной временной папке. Файл удаляется после завершения, ошибки или прерывания через Ctrl+C. Собственные реализации на Python работают существенно медленнее `hashlib`, поэтому эта проверка запускается отдельно от `pytest`.

Для короткой проверки самого скрипта:

```bash
python scripts/check_large_hash.py --size-mb 1
```

Для запуска только одного алгоритма:

```bash
python scripts/check_large_hash.py --algorithm sha256
```

Короткий прогон не подтверждает требование обработки файла больше 1 ГБ. Результаты полного прогона нужно фиксировать отдельно после его завершения.

### Результаты проверки большого файла

20 октября 2026 года выполнен полный запуск `python scripts/check_large_hash.py` с параметрами по умолчанию. Размер файла: 1 100 000 000 байт. Данные файла — повторяющаяся последовательность байтов от `0x00` до `0xff`, обрезанная до заданного размера.

Оба алгоритма обработали файл полностью и выдали хеши, совпадающие с `hashlib`:

| Алгоритм | Время обработки | Результат |
| --- | ---: | --- |
| SHA-256 | 2113,02 с (35 мин 13 с) | Совпадает с `hashlib.sha256` |
| SHA3-256 | 2783,92 с (46 мин 24 с) | Совпадает с `hashlib.sha3_256` |

SHA-256:

```text
3aab6da7a448d744838d781d07cd17af07a6f5f684a969e99811da47abcccd13
```

SHA3-256:

```text
13b769cb7ec3b67ce5170ff710ef7d311e40ddf1e76b804c0a08dad8e4ccd5e1
```

Чтение выполнялось частями не больше 8192 байт. Это подтверждает обработку файла больше 1 ГБ для обоих алгоритмов в данном сценарии. Пиковое потребление памяти отдельно не измерялось. Эта проверка дополняет известные тестовые векторы и не заменяет полный набор векторов NIST.

## Проверка векторов NIST для хешей

Файлы в `tests/vectors/` содержат официальные побайтовые наборы ShortMsg, LongMsg и Monte для SHA-256 и SHA3-256. Источники, контрольные суммы файлов и команды запуска приведены в `tests/vectors/README.md`.

Проверены все 366 коротких и длинных сообщений, а также все 200 контрольных значений Monte Carlo. Для каждого алгоритма Monte Carlo выполняется 100 000 хеширований по процедуре NIST. Наборы для входа с длиной, некратной байту, не используются: API проекта работает с байтами.

20 октября 2026 года полный запуск `pytest -q` завершился успешно: **513 passed за 71,19 секунды**. Проверки работают без подключения к сети. Большой файл размером 1,1 ГБ проверяется отдельно, его результаты приведены выше. Прохождение этих тестов не является сертификацией CAVP.
